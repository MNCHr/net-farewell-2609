# 신원 모델 변경(사번 → 이메일) + 퇴직자별 표 복사 — 설계

- 작성일: 2026-08-13
- 상태: 승인됨 (구현 계획 작성 대기)
- 선행 문서: [2026-08-12 최초 설계](2026-08-12-farewell-gift-survey-design.md)

## 1. 배경과 목적

사이트는 이미 배포되어 동작한다 (GitHub Pages + Apps Script + 구글시트, 사내망 진단 통과).
**아직 아무에게도 공지하지 않았고 시트에는 관리자 테스트 행만 있다.** 따라서 기존 응답의
이전(migration)은 고려하지 않는다.

담당자가 두 가지를 요청했다.

1. **로그인 신원을 사번에서 회사 이메일 아이디로 바꾼다.** 입력은 `abc`, 저장은 `abc@etri.re.kr`
2. **관리자 화면에서 퇴직자별 참여자 표를 따로 복사할 수 있게 한다.** 각 퇴직자에게 마음을 보탠
   사람들에게 메일을 보내기 위해서다

### 두 요청은 하나로 이어진다

사번은 식별자일 뿐이었지만 이메일은 **그 자체로 보낼 수 있는 주소**다. 신원을 이메일로 바꾸는
순간 퇴직자별 명단이 곧 메일 수신자 목록이 된다. 이름을 뽑아 다시 주소를 찾는 단계가 사라진다.
1번이 2번을 쓸모 있게 만든다.

### 성공 기준

- 참여자가 `abc`, `ABC`, `abc@etri.re.kr` 중 무엇을 입력하든 **같은 한 사람**으로 모인다
- 시트 A열에 `abc@etri.re.kr` 형태로 저장된다
- 관리자가 퇴직자별로 참여자 표를 뽑아 엑셀에 붙여넣고 이메일 열을 긁을 수 있다
- 기존 106개 테스트가 새 신원 모델로 갱신되어 전부 통과한다

### 범위 밖

- 기존 응답 이전 (해당 없음 — 실사용 전)
- 이메일 실제 발송 (담당자가 메일 클라이언트로 직접 보낸다)
- 도메인이 여럿인 조직 지원 (아래 4장에서 단일 도메인으로 확정)

## 2. 신원 모델

### 정규화 규칙 — `normalizeEmail`

**이 문서가 규칙의 정본이다.** 같은 규칙을 `assets/normalize.js`(브라우저)와
`apps-script/Code.gs`(서버)에 각각 구현하고, 공용 케이스 표로 양쪽을 함께 검증한다.
(이 두 벌 구조와 그 이유는 최초 설계 §4와 같다.)

1. 앞뒤 공백을 제거하고 **소문자로 바꾼다**
2. `@` 가 있으면 **첫 `@` 앞부분만** 취한다
3. 남은 문자열이 `^[a-z0-9._+-]{1,64}$` 인지 검사한다. 아니면 오류 `BAD_EMAIL`
4. `아이디 + '@' + DOMAIN` 을 돌려준다 (`DOMAIN`은 `etri.re.kr`)

```
'abc'              → 'abc@etri.re.kr'
'ABC'              → 'abc@etri.re.kr'    소문자화
' abc '            → 'abc@etri.re.kr'    공백 제거
'abc@etri.re.kr'   → 'abc@etri.re.kr'    전체 이메일 붙여넣기
'abc@etri.kr'      → 'abc@etri.re.kr'    도메인 무시 (아래 참조)
'hong.gildong'     → 'hong.gildong@etri.re.kr'
''                 → null
'a b'              → null                공백은 아이디에 못 쓴다
'가나다'            → null                한글 불가
'a'.repeat(65)     → null                65자 초과
```

**반환값이 곧 신원이자 저장값이다.** 별도의 아이디 필드를 두지 않는다 — 도메인이 항상 고정이라
중복 정보가 된다.

### 왜 도메인을 신원에서 무시하는가

담당자는 다른 도메인을 쓰는 구성원이 있는지 모른다고 했다. 도메인을 신원에 포함시키면
같은 사람이 `abc` 로 한 번, `abc@etri.kr` 로 한 번 입력했을 때 **두 행으로 갈라진다.**
이는 사번의 앞자리 0 문제와 정확히 같은 함정이다.

아이디만 신원으로 삼으면 그 문제가 원천 차단된다. 대가는 다른 도메인을 쓰는 사람의 저장값이
`@etri.re.kr` 로 잘못 기록되는 것인데, 화면 힌트가 저장될 값을 그대로 보여주므로 본인이
바로 알아차릴 수 있고, 관리자가 그 행만 고치면 된다. 한두 명 있을까 말까 한 경우를 위해
설계를 복잡하게 만들지 않는다.

### 아이디 검증은 넉넉하게

허용: 영문 소문자, 숫자, `.`, `_`, `-`, `+`. 길이 1~64.

**사번 때와 판단이 반대다.** 사번은 "숫자 5자리"라는 확실한 규칙이 있어 엄격한 검증이 도움이
됐다. 이메일 아이디는 형태가 제각각이라(`hong.gildong`, `hgd_2`, `gildong-h`) 엄격하면
멀쩡한 사람이 못 들어온다. 반대로 느슨해서 생기는 최악은 오타 아이디로 빈 행 하나가 생기는
것이고, 관리자가 지우면 된다. **틀렸을 때 덜 아픈 쪽으로 기운다.**

### 사라지는 것들

사번 전용이던 방어 장치가 불필요해진다. 이번 변경으로 코드는 오히려 줄어든다.

- 앞자리 0 채우기 (`while (digits.length < 5) digits = '0' + digits`)
- 시트 A열 텍스트 서식 요구 (일반 서식이어도 이메일은 온전히 남는다)
- `EMPNO_LENGTH` 상수

**남기는 것:**

- `toHalfWidthDigits_` — 비밀번호(숫자 4자리)가 아직 쓴다. 전각으로 친 비밀번호를 받아준다
- **`readRows_` 의 재정규화** — 이유는 바뀌지만 계속 필요하다. 원래는 구글이 `01234` 를
  숫자로 바꾸는 것에 대한 방어였는데, 이제는 **관리자가 시트를 직접 편집할 때**를 막는다.
  대리 입력이나 구제를 위해 손으로 `ABC@etri.re.kr` 이라고 적어 넣으면 신원이 갈라진다.
  읽을 때 한 번 더 정규화하면 그 경우가 흡수된다

이름 정규화(공백 제거 + NFC)와 비밀번호 정규화(숫자 4자리)는 **그대로 둔다.**

## 3. 이름 정리 — `empNo` → `email`

코드 전반에 `empNo` 가 약 220곳 있다. 전부 `email` 로 바꾼다.

내부 이름을 `empNo` 로 두고 규칙만 바꾸면 변경이 훨씬 작지만 **그렇게 하지 않는다.**
`empNo` 라는 이름이 이메일을 담고 있으면 다음에 이 코드를 읽는 사람이 반드시 헷갈린다.
이 프로젝트의 리뷰에서 "이름이 하는 일과 다른 것"을 반복해서 결함으로 잡아왔고,
여기서 스스로 만들 이유가 없다.

**테스트 106개가 안전망이다.** 한 곳이라도 빠뜨리면 테스트가 잡는다. 기계적 치환이라
위험이 낮다.

바뀌는 이름들:

| 지금 | 바뀐 뒤 |
|---|---|
| `normalizeEmpNo` / `normalizeEmpNo_` | `normalizeEmail` / `normalizeEmail_` |
| `COL.EMPNO` | `COL.EMAIL` |
| `findByEmpNo_` / `findAnyByEmpNo_` | `findByEmail_` / `findAnyByEmail_` |
| 요청·응답의 `empNo` 필드 | `email` |
| 오류 코드 `BAD_EMPNO` | `BAD_EMAIL` |
| 경고 `SAME_NAME_DIFF_EMPNO` | `SAME_NAME_DIFF_EMAIL` |
| 경고 `SAME_EMPNO_DIFF_NAME` | `SAME_EMAIL_DIFF_NAME` |
| 화면 문구 "사번" | "이메일 아이디" |

`EMPNO_CASES` → `EMAIL_CASES`. 사번 전용 케이스(앞자리 0, 전각 숫자, 6자리 초과)는
이메일 규칙에 맞는 케이스로 대체한다.

## 4. 설정

`assets/config.js` 에 도메인을 추가한다.

```js
/** 로그인 아이디에 붙일 회사 이메일 도메인. '@' 는 포함하지 않는다. */
export const EMAIL_DOMAIN = 'etri.re.kr';
```

서버에도 같은 값이 필요하다 (서버가 최종 판정을 하므로). `apps-script/Code.gs` 상단에
상수로 둔다.

```js
var EMAIL_DOMAIN = 'etri.re.kr';
```

두 곳에 같은 값이 존재하는 것은 정규화 규칙이 두 벌인 것과 같은 이유다 —
번들러도 공유 모듈도 없다. **두 값이 어긋나면 화면에 보이는 것과 저장되는 것이 달라진다.**
공용 케이스 표가 두 구현을 함께 검증하므로 어긋나면 테스트가 잡는다.

## 6. 화면

### 참여자 (`index.html` / `assets/app.js`)

로그인 칸의 라벨과 힌트가 바뀐다. 단계 구조(랜딩 → 로그인 → 확인 → 선택 → 완료)는 그대로다.

```
아이디  [ abc                    ]
        └ abc@etri.re.kr 으로 조회합니다 ✓
           @etri.re.kr 은 빼고 아이디만 쓰셔도 됩니다
```

- 입력 중 실시간으로 **저장될 값 전체**를 보여준다. 사번 때 정규화된 사번을 보여주던 것과 같은 장치다
- 전체 이메일을 붙여넣어도 같은 결과가 뜬다
- 형식이 틀리면 빨간 경고: "이메일 아이디를 확인해주세요. 영문·숫자와 `. _ - +` 만 쓸 수 있습니다"
- 확인 화면(신규일 때만)에 사번 대신 이메일이 뜬다

입력 칸의 `inputmode` 를 `numeric` 에서 기본값으로 되돌린다 (더 이상 숫자가 아니다).
비밀번호 칸은 숫자 4자리 그대로이므로 `inputmode="numeric"` 을 유지한다.

### 관리자 (`admin.html` / `assets/admin.js`)

표의 첫 열 머리글이 "사번" → "이메일" 로 바뀐다. 대리 입력 폼의 라벨도 같다.

## 7. 퇴직자별 표 복사

복사 버튼이 하나에서 셋으로 늘어난다.

```
[ 전체 표 복사 ]  [ 김응하 박사님 참여자 표 (76) ]  [ 황정연 박사님 참여자 표 (71) ]
```

세 버튼이 **완전히 같은 형식**의 탭 구분 표를 만든다. 다른 것은 어떤 행이 들어가느냐뿐이다.

```
이메일	이름	김응하 박사님	황정연 박사님	최종수정
hskang@etri.re.kr	강현식	O	O	2026-08-14
nsko@etri.re.kr	고남석	O		2026-08-14
```

열 순서는 **화면의 표와 같게** 둔다. 화면은 이메일이 첫 칸이므로 복사본도 그렇다.
화면과 복사본이 다르면 붙여넣고 나서 "어라, 순서가 다르네" 하는 순간이 생긴다.

- 퇴직자별 버튼은 그 퇴직자를 선택한 행만 담는다 (`pickA` 또는 `pickB` 가 참인 행)
- **퇴직자 두 칸을 모두 남긴다.** 그 표만 봐도 "이 사람은 두 분 다 하는구나"가 보인다
- 버튼 라벨에 해당 인원수를 함께 표시한다. 누르기 전에 몇 명인지 보인다
- 세 버튼 모두 `stale` 상태에서는 막힌다. 낡은 명단으로 메일을 보내면 안 된다
- 참여자가 0명이면 버튼을 누를 수 없게 한다 (헤더만 있는 표를 복사할 이유가 없다)

구현은 표를 만드는 함수 하나에 **행 필터만 갈아끼우는** 형태다. 세 벌의 출력 코드를 두지 않는다.

담당자는 이 표를 엑셀에 붙여넣고 이메일 열을 긁어 메일 수신자 칸에 넣는다. 따라서
구분자(`,` vs `;`) 문제는 발생하지 않는다.

## 8. 테스트

기존 106개를 새 신원 모델로 갱신한다. 테스트 **수는 크게 변하지 않는다** — 사번 전용 케이스가
빠지고 이메일 전용 케이스가 들어온다.

### 정규화 케이스 표 (`EMAIL_CASES`)

빠지는 것: 앞자리 0 채우기, 전각 숫자, 6자리 초과, 하이픈 섞인 숫자

들어오는 것:

| 입력 | 기대 | 이유 |
|---|---|---|
| `'abc'` | `'abc@etri.re.kr'` | 기본 |
| `'ABC'` | `'abc@etri.re.kr'` | 대문자로 쳐도 같은 사람 |
| `'abc@etri.re.kr'` | `'abc@etri.re.kr'` | **전체 이메일 붙여넣기 — 가장 흔할 실수** |
| `'abc@etri.kr'` | `'abc@etri.re.kr'` | 도메인이 달라도 같은 사람 |
| `' abc '` | `'abc@etri.re.kr'` | 앞뒤 공백 |
| `'hong.gildong'` | `'hong.gildong@etri.re.kr'` | 점 |
| `'hgd_2'` | `'hgd_2@etri.re.kr'` | 밑줄 |
| `'gildong-h'` | `'gildong-h@etri.re.kr'` | 하이픈 |
| `'a+b'` | `'a+b@etri.re.kr'` | 플러스 |
| `'abc@'` | `'abc@etri.re.kr'` | `@` 뒤가 비어도 앞이 유효하면 통과 (규칙 2의 자연스러운 귀결) |
| `'@etri.re.kr'` | `null` | `@` 앞이 비었다 |
| `''` | `null` | 빈 값 |
| `'  '` | `null` | 공백뿐 |
| `'가나다'` | `null` | 한글 불가 |
| `'a b'` | `null` | 공백 불가 |
| `'a'.repeat(65)` | `null` | 64자 초과 |
| `null` / `undefined` | `null` | |

### 시나리오 테스트

기존 13개 시나리오의 뜻은 그대로 두고 사번을 이메일로 바꾼다. 시나리오 3만 내용이 바뀐다:

- **지금**: 앞의 0을 뺀 사번이 같은 행으로 모인다
- **바뀐 뒤**: `abc` 와 `abc@etri.re.kr` 과 `ABC` 가 같은 행으로 모인다

이 시나리오가 이번 변경의 핵심을 지킨다. 사번 때 앞자리 0이 그랬듯, 이번엔 **전체 이메일
붙여넣기**가 가장 흔한 입력 편차다.

### 새로 필요한 테스트

퇴직자별 표 복사는 브라우저 전용 코드라 단위 테스트 대상이 아니다 (최초 설계에서 화면은
단위 테스트하지 않기로 했다). 대신 표를 만드는 순수 함수를 분리해 테스트한다.

- 전체 필터: 모든 active 행
- A 필터: `pickA` 인 행만
- B 필터: `pickB` 인 행만
- 헤더 행이 항상 첫 줄
- 탭 구분, 줄바꿈으로 행 구분
- 선택 표시가 `O` / 빈칸
- 빈 결과일 때 헤더만

## 9. 배포 순서

**순서가 틀리면 잠깐 깨진다.** 지금 아무도 쓰지 않으므로 실질 위험은 없으나, 순서를 지킨다.

1. **구글시트**: 테스트 행 전부 삭제, A열 헤더를 `email` 로 수정, `log` 시트도 헤더만 남기고 비움
2. **Apps Script**: 새 `Code.gs` 붙여넣기 → **배포 관리 → 편집 → 버전: 새 버전** → 배포
   (저장만 해서는 `/exec` 주소의 내용이 바뀌지 않는다)
3. **GitHub**: push (Pages 자동 갱신)
4. **확인**: `test.html` 에서 `headerOk` 가 true 인지 — 1번을 빠뜨렸으면 여기서 잡힌다
5. **점검**: 본인 아이디로 로그인 → 제출 → 시트에 `abc@etri.re.kr` 로 저장됐는지 →
   재로그인 시 이전 선택이 보이는지 → 관리자 화면에서 퇴직자별 표 복사

2번을 빠뜨리면 화면은 새 것인데 서버는 옛 것이라 모든 요청이 `BAD_EMAIL` 로 떨어진다.
1번을 빠뜨리면 `headerOk` 가 false 로 잡힌다.
